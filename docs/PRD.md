## 1. 목표(Goal)

Android 우선(추후 iOS)으로, 고정된 기기 카메라 앞에서 풀업을 하면 온디바이스 포즈 추정으로 rep을 실시간 판정해 음성("1개, 2개…")으로 알려주고, 세트 종료 시 개수·규칙 기반 자세 점수·rep별 문제점·교정 팁을 리포트로 제공한다. 엄격 모드 기록은 소셜 로그인 후 all-time 리더보드(MVP 단계에서는 전 기록 "미검증" 라벨)에 올려 공유할 수 있다. 1인 개발/운영 프로젝트이며, 서버는 무료 티어 안에서만 운영한다. 동시에 이 앱을 Kotlin Multiplatform(KMP)+Compose Multiplatform(CMP)로 만드는 것의 실효성을 판정한다(판정 결과는 `docs/architecture-kmp.md`, D4).

## 1.1 페르소나

| 페르소나 | 설명 | 핵심 니즈 |
|----------|------|-----------|
| 혼자 운동하는 사람 (기본) | 집/헬스장에서 혼자 풀업 세트를 하고, 개수를 세어줄 사람이 없음 | 정확한 카운트, 즉각적인 음성 피드백, 자세 교정 팁 |
| 기록 갱신 도전자 | 자신의 최고 기록을 추적하고 다른 사람과 비교하고 싶음 | 로컬 개인 최고기록(PB) 추이, all-time 리더보드 순위 |
| 자세 개선 희망자 | 풀업 개수보다 올바른 자세(가동범위, 반동 없음)에 관심 | rep별 실패 원인, 교정 팁, 연습 모드에서 부담 없이 반복 |
| 앱 운영자(개발자 본인) | 1인으로 개발·운영. 서버 비용·부정 사용·신고 대응을 감당해야 함 | 무료 티어 유지, 최소한의 운영 부담, 수치로 확인 가능한 게이트 |

## 1.2 KMP/CMP 실효성 판정 (요약)

**결론: 조건부 권장.** Android/Kotlin 숙련 + iOS 약함 + 1인 개발 + "Android 먼저, iOS 나중" 조합에서 KMP+CMP는 iOS 확장 시 UI 재작성 부담을 없애는 이점이 크다. 근거·공유/네이티브 경계·반전 조건의 전체 판정은 `docs/architecture-kmp.md`(D4)에 기록한다.

## 2. 범위 / 비범위

### 2.1 Non-Goals (스펙 승계, 5개)

- 서버 측 영상 분석, LLM 기반 코칭
- 풀업 외 운동(친업/딥스 등) — 추후 확장 여지로만 언급, 이번 범위 아님
- 전 세션 영상 업로드, 소셜 피드/댓글
- 손에 들고 촬영, 자유 각도 지원 (기기는 삼각대/바닥 고정, 전신이 프레임에 들어오는 조건만 지원)
- 웹/데스크톱 클라이언트

### 2.2 MVP vs Phase 2 범위 표

| 구분 | MVP (Phase 1) | Phase 2 (검증 시스템) |
|------|----------------|------------------------|
| 리더보드 보드 | all-time 1개, **엄격 모드 기록만**, 전 기록 `UNVERIFIED`("미검증" 라벨 표시) | Verified / 전체 2탭. **Verified가 기본 탭**. Verified 기준 Top N만 공식 순위 |
| 증빙 영상 | 없음. **영상은 기기에만 보관**. 업로드·검수 큐·서버 Storage·재인코딩 없음 | 상위 N위 진입 또는 Top N 내 PB 갱신 시 영상 증빙 업로드, 검수 큐(주간 신규 접수 ≤25건), 판정 후 원본 삭제(R1) |
| 부정 방지 | RPC 전용 제출(클라이언트 직접 INSERT 불가) + 사용자별 레이트 리밋(엄격 모드 제출만) + Play Integrity API 증명 + 신고 버튼·운영자 숨김 + 물리 일관성 거부 + 이상 FLAG + rep 메타데이터 타임라인 | MVP 부정 방지 전체 + 영상 증빙 + 해시 바인딩(원본 SHA-256 대조) |
| 로컬 영상 보관 | 설정 "엄격 세션 영상 보관": 기본값 = 전 엄격 세션 보관, 저장 공간 부담 시 개인 최고기록(PB) 세션만 보관하도록 자동 전환(2.4절 임계값) | 보관된 원본을 재인코딩 없이 그대로 업로드해 증빙 제출 |
| 계정/로그인 | 카운팅·리포트·히스토리는 로그인 불필요. 리더보드 업로드 시에만 소셜 로그인(Google) | 동일 |
| 비용 게이트 | **G0**: Supabase Free, Storage 미사용, 최악 DB·Egress 각 한도 70% 이하 → 충족(추정 DB ≈12%, Egress ≈5%) | **G1(a)~(j)**: Storage·Egress 각 70% 이하, 검수 부하 ≤25건/주, 정상상태 수요/처리량 ≤70% 등. 진입 트리거 충족 시 재평가 |
| 주간 보드 | 없음(all-time만) | Phase 2 이후 별도 검토 대상(미검증 라벨 + 증빙 면제 방식으로 재검토, 이번 문서 범위 아님) |

### 2.3 Phase 2 진입 트리거

**월 신고(report) 건수 > 20건**(단일 조건, 2026-09-27 사용자 확정). 이 조건을 충족하면 Phase 2(영상 증빙 검증 시스템) 착수를 검토한다. 백엔드 세부 게이트(G1)와 재평가 트리거는 `docs/backend-cost-decision.md`(D5)에 기록한다.

## 3. 기능 요구사항 (F1–F4)

### F1. 실시간 카운팅

- **모드 선택**
  - **엄격 모드**(리더보드 반영 대상): 턱이 바 위로 올라가고 하단에서 팔이 거의 완전히 펴져야 1회로 카운트한다. 불완전 rep은 카운트하지 않고 "노카운트" 음성/시각 피드백을 준다.
  - **연습 모드**: 올라갔다 내려오면 카운트하고, 불완전 rep은 자세 점수에서 감점 처리한다. 세션·재측정 횟수 제한 없음.
- 음성 카운트(TTS 또는 사전 녹음 음원), 화면에 큰 숫자 + 스켈레톤 오버레이를 표시한다.
- 시작 전 캘리브레이션: 전신/바 위치 인식 확인 → 카운트다운 → 시작. 일정 시간 매달림 해제(바에서 내려옴) 감지 시 자동 종료, 수동 종료도 지원한다.
- 세션 중 영상을 로컬에 녹화한다(증빙 제출용, F3 참고).
- 상세 판정 규칙(임계값, 상태머신, 지연 예산)은 `docs/spec-rep-detection.md`(D2)에 정의한다.

### F2. 세션 리포트

- 총 개수(모드별), 세트 시간, 평균 템포를 표시한다.
- 규칙 기반 자세 점수(0~100): 가동 범위(ROM), 키핑/반동, 템포 일관성, 좌우 대칭, 하단 완전 신전 등 항목별 산정.
- rep별 타임라인: 예) "3회차: 턱이 바에 미달" 등 실패 원인 태깅.
- 교정 팁: 가장 많이 감점된 항목 기준으로 사전 작성된 팁 라이브러리에서 1~3개 선택.
- 채점 산식·태그·팁 선택 규칙은 `docs/spec-posture-scoring.md`(D3)에 정의한다.

### F3. 기록/히스토리 (로컬)

- 세션 목록, 모드별 개인 최고기록(PB), 간단한 추이 그래프를 제공한다.
- 로컬 DB(Room KMP)에 저장하고, 영상 파일은 참조(사용자가 삭제 가능)한다.
- **로컬 영상 보관 정책**: 설정 항목 "엄격 세션 영상 보관"의 기본값은 **전 엄격 세션 영상 보관**이다. 다음 중 하나라도 해당하면 자동으로 **개인 최고기록(PB) 세션 영상만 보관**하도록 전환하고, 그 밖의 기존 엄격 세션 영상은 사용자 확인 후 정리(삭제) 대상으로 안내한다.
  - **앱 전용 영상 폴더 용량이 2 GB를 초과**하는 경우, 또는
  - **기기 여유 저장공간이 전체 저장공간의 10% 미만**인 경우.
  - 위 두 수치(2 GB, 10%)는 **초기값**이며, 실제 사용자 저장공간 분포 데이터가 쌓이면 조정할 수 있다.
  - 자동 전환 시 사용자에게 알림을 표시하고, 설정에서 "전 세션 보관"으로 되돌릴 수 있다.
  - 보관된 엄격 세션 영상은 Phase 2 개시 후 과거 PB를 증빙으로 제출하는 데 사용할 수 있다(4.4절, `docs/backend-cost-decision.md` 2.2B 참고).

### F4. 리더보드/공유 (MVP: 미검증 all-time 보드)

- **엄격 모드 기록만** 업로드 가능하며, 업로드 시 소셜 로그인(Google, 이후 iOS에서 Apple)이 필요하다.
- 순위: **all-time 1개 보드**, 최대 개수 기준. MVP 단계에서는 주간 보드를 제공하지 않는다.
- **미검증(UNVERIFIED) 표시**: MVP에서는 영상 증빙 없이 전 기록이 등록 즉시 순위에 노출되며, 모든 기록에 "미검증" 라벨을 병기한다. 영상 증빙에 의한 검증(Verified 표시)은 Phase 2에서 제공한다.
- **부정 방지(MVP)**: RPC 전용 제출(클라이언트가 테이블에 직접 쓸 수 없음), Play Integrity API 증명 첨부, 물리적으로 불가능한 rep 시간 거부(2단계 임계값, `docs/spec-rep-detection.md` 참고), 이상 기록(첫 업로드 Top 10 진입, 직전 PB 대비 +max(5회, 30%) 이상 급등) 플래그 후 운영자 알림(단, 노출은 유지하고 숨기지 않음), rep 메타데이터 타임라인 업로드, 신고 버튼 + 운영자 수동 숨김. **고정된 rep 상한("엄격 40회 초과 자동 보류" 등)은 두지 않는다** — 강한 사용자가 실제로 많이 하는 것을 부당하게 불이익 주지 않기 위함이다.
- **엄격 모드 리더보드 제출의 레이트 리밋**: 사용자별 제출 횟수 제한(예: 1일 3건)은 **엄격 모드 리더보드 제출에만 적용**한다. 연습 모드 세션의 저장·재측정 횟수는 무제한이며, 레이트 리밋의 영향을 받지 않는다.
- 공유: 결과 카드 이미지 생성 후 OS 공유 시트로 공유한다.
- 부정 방지·백엔드 권한 모델의 세부 사항은 `docs/backend-cost-decision.md`(D5)에 정의한다.

## 5. MVP 개인정보 요구사항 (1)–(4)

아래 4개 항목은 MVP 출시 전 반드시 충족해야 하는, 테스트 가능한 요구사항이다. **이 절(MVP)에는 영상 업로드에 대한 동의가 포함되지 않는다** — MVP는 영상을 서버로 전송하지 않기 때문이다(영상 관련 동의는 6절 "Phase 2 영상 동의" 참고).

1. **온디바이스 저장 고지**: 앱은 사용자의 **첫 녹화 시작 전**에, 세션 영상이 기기에만 저장되며 서버로 전송되지 않는다는 점과 "엄격 세션 영상 보관" 설정(기본값·현재 사용 용량)을 안내하는 고지 화면을 표시하고, 사용자가 이를 확인(예: "확인" 버튼)해야 녹화가 시작된다.
2. **업로드 고지**: 앱은 사용자가 **리더보드 업로드를 처음 시도할 때**, 서버로 전송되는 데이터 항목이 **닉네임, 기록(개수·모드·일시), rep 메타데이터 타임라인, 선택적으로 제출 원본의 SHA-256 해시(`videoSha256`)** 이며 **영상 파일 자체는 전송하지 않는다**는 점, 그리고 기록의 공개 범위(all-time 리더보드에 노출됨)를 명시한 고지 화면을 표시하고, 사용자가 동의해야 업로드가 진행된다.
3. **계정 삭제**: 앱은 로그인한 사용자가 **인앱 설정 화면에서** 계정 삭제를 요청할 수 있는 기능을 제공하고, 로그인 여부와 무관하게 접근 가능한 **웹 삭제 요청 페이지**를 제공한다(Google Play "계정 삭제" 정책 요구사항 충족, VERIFIED — https://support.google.com/googleplay/android-developer/answer/13327111 , 접근일 2026-09-27). 삭제 요청이 처리되면 해당 사용자의 리더보드 기록, rep 메타데이터 타임라인, 신고 이력이 삭제된다.
4. **Data safety 신고 초안**: 앱은 Google Play Console의 Data safety 섹션에 제출할 초안 문서를 보유하며, 여기에는 최소한 다음 데이터 유형이 수집/공유 항목으로 명시된다 — 계정 식별자(로그인 제공자 ID), 닉네임, 리더보드 기록(개수·모드·일시), rep 메타데이터 타임라인, 기기 무결성 판정 결과(Play Integrity). 이 초안은 MVP 출시 전 검토·확정한다.

## 6. Phase 2 영상 증빙 동의 (별도 절)

Phase 2(영상 증빙 검증 시스템)가 착수되면 아래 동의 흐름을 추가한다. **이 절은 MVP 범위가 아니다.**

- 증빙 영상을 처음 업로드하기 전, 별도의 동의 화면을 표시한다. 동의 화면에는 다음을 명시한다: (a) 영상의 용도(순위 진입/PB 갱신에 대한 부정 사용 여부를 운영자가 수동 검수), (b) 보관 기간(판정 즉시 원본 삭제, 최대 대기 7일, 이후 SHA-256 해시 + 검수자 전용 썸네일만 영구 보관), (c) 열람 권한(검수자만 열람, 공개되지 않음).
- 사용자가 동의를 철회하면, 서버에 남아 있는 해당 영상·썸네일을 즉시 삭제하고 관련 리더보드 순위 노출을 즉시 중단한다.
- Data safety 문서(5절 항목 4)에 Phase 2 시점부터 "영상(생체 인식 정보 아님, 운동 동작 영상)" 항목을 추가한다.
- 과거 PB 영상 증빙 상한 고지: 로컬에 보관된 엄격 세션 영상은 **720p/약 1.0 Mbps** 프리셋으로 녹화되며, Phase 2 과거 PB 증빙 업로드 버킷의 **파일 크기 상한은 16 MB**이다. 이 비트레이트 기준으로 **세트 길이가 128초를 넘는 과거 PB 세션 영상은 16 MB를 초과하므로 Phase 2 증빙으로 제출할 수 없다.** 해당 세션은 증빙 제출 시 재녹화를 안내받는다.

## 8. 용어집

| 용어 | 정의 |
|------|------|
| 엄격 모드 (Strict mode) | 턱이 바 위로 올라가고 하단에서 팔이 거의 완전히 펴져야 1회로 인정하는 카운팅 모드. 리더보드 반영 대상. |
| 연습 모드 (Practice mode) | 올라갔다 내려오면 카운트되는 모드. 불완전 rep은 자세 점수에서 감점. 리더보드 반영 대상 아님, 횟수 제한 없음. |
| PB (Personal Best) | 개인 최고기록. 모드별로 별도 관리. |
| UNVERIFIED (미검증) | MVP 리더보드 기록의 기본 상태. 영상 증빙 없이 제출·노출되는 기록임을 나타내는 라벨. |
| Verified | Phase 2에서 영상 증빙이 승인(APPROVED)된 기록의 상태. Verified 탭의 공식 순위 산정 기준. |
| RPC (Remote Procedure Call) | 클라이언트가 테이블에 직접 쓰지 않고, 서버 측 함수를 통해서만 데이터를 제출하는 방식. 부정 방지를 위한 서버 권한 모델의 핵심. |
| 이상 FLAG | 첫 업로드가 Top 10에 진입하거나 PB가 급등(+max(5회, 30%) 이상)하는 등 이상 패턴이 감지된 기록에 붙는 표시. 숨김 처리는 아니며 운영자 알림만 발생시킨다. |
| T_floor | 엄격 rep 소요 시간의 물리적 하한 임계값(초기값 0.5초). 이보다 짧은 rep은 물리적으로 불가능한 것으로 보고 거부한다. |
| T_rep_min | T_floor와 함께 쓰이는 2단계 임계값(초기값 0.8초). T_floor 이상 T_rep_min 미만인 rep은 거부하지 않고 FLAG만 표시(노출 유지). |
| VideoReplaySource | 실기기 카메라 대신 녹화된 영상을 입력으로 재생하여 포즈 추정 파이프라인을 결정적으로 재현·측정하기 위한 입력 추상화. |
| G0 | MVP 리더보드 비용 게이트(Supabase Free, Storage 미사용, DB·Egress 각 한도 70% 이하 등). |
| G1 | Phase 2(영상 증빙 검증 시스템) 착수 비용 게이트(a)~(j). |
| videoSha256 | 리더보드 제출 RPC의 선택 텍스트 필드. 로컬에 보관 중인 세션 영상 원본의 SHA-256 해시값(영상 자체는 전송하지 않음). |
| bindingStrength | Phase 2 과거 PB 증빙 판정 시, 해시 일치로 검증되었는지(STRONG, 문서 내 기본 표기는 강한 바인딩) 또는 타임라인 교차 확인만으로 통과했는지(WEAK)를 나타내는 내부 플래그. |
