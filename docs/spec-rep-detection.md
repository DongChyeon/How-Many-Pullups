## 1. 용어와 기호

| 기호 | 의미 | 단위 |
|---|---|---|
| S | 어깨폭. 캘리브레이션 때 측정해 세트 동안 고정한다(§4.3) | 길이. 모든 거리 임계값은 S의 배수 |
| `y_bar` | 바 높이. 캘리브레이션 매달림 동안 양 손목 y 중앙값 | 이미지 좌표 |
| h | 턱 높이 여유 = (`y_bar` − `y_chin`) / S. 양수면 턱이 바보다 위(이미지 y축은 아래로 증가) | S |
| θ | 팔꿈치 각도 ∠(어깨-팔꿈치-손목), 좌우 평균. 좌우 값은 따로 기록한다 | ° |
| a | 보조 지표 = (어깨 중점 y − 손목 중점 y) / S. 매달리면 크고 TOP에서 작다 | S |
| px | 골반 중점 수평 변위 = (골반 중점 x − 캘리브레이션 기준 x) / S | S |
| r | (연습 모드) 상승 비율 = (h − `h_hang`) / (k − `h_hang`) | 0–1 |
| β_bar | 카메라에서 바를 보는 시선의 앙각. 위를 보면 양수(§3.3) | ° |
| ψ | 몸통 요(yaw) 각. 정면이면 0°(§4.3) | ° |
| 엄격 / 연습 | 모드 이름. 리더보드에는 엄격 모드 기록만 올라간다(D1) | — |
| 무장(armed) | 직전 BOTTOM에서 신전이 확정된 상태. 카운트는 무장 상태에서만 가능하다 | — |
| TOP 확정 | DWELL_OK 또는 FAST_TOP(§7.2) | — |
| COUNT | 단일 카운트 이벤트. 정의는 §8에만 둔다 | — |
| NC(사유) | 노카운트 기록. 사유 enum은 §12.1 | — |

**단위 규칙.** 모든 시간 임계값은 ms로 정의하고, 모든 거리 임계값은 S의 배수로 정의한다. 프레임 수로 정의한 임계값은 없다. 이렇게 하면 fps가 바뀌어도 판정이 달라지지 않는다. 시간은 항상 프레임의 **센서 타임스탬프** 차이로 잰다(§2.3).

## 2. 입력 모델

### 2.1 포즈 랜드마크 (MediaPipe 33점)

포즈 엔진 기본안은 MediaPipe Pose Landmarker(lite)다. 최종 결정은 D4가 한다(M0 + D6 비교). 이 엔진은 33개 랜드마크를 출력하며(VERIFIED, §15 R1), ML Kit Pose Detection(beta)도 같은 33점 체계다(VERIFIED, §15 R3). 따라서 엔진을 바꿔도 이 스펙은 그대로 적용된다.

D2가 사용하는 인덱스(MediaPipe 공식 인덱스, VERIFIED §15 R1):

| 그룹 | 인덱스 | 용도 |
|---|---|---|
| FACE | 0 코, 9 입(왼쪽), 10 입(오른쪽) | 턱 대리점 `y_chin`(§5.3), 후면 뷰 판별(§3.4) |
| SHOULDER | 11 왼 어깨, 12 오른 어깨 | S, θ, a, 요 각 ψ |
| ARM | 13·14 팔꿈치, 15·16 손목 | θ, `y_bar`, a, 매달림 해제 |
| HIP | 23 왼 골반, 24 오른 골반 | px, 대상 중심점 |
| (참고) | 27·28 발목 | 촬영 구도 안내(판정에는 쓰지 않음) |

- 랜드마크마다 정규화 좌표 (x, y ∈ [0,1]), `visibility`, 그리고 월드 좌표(m)를 쓴다. `visibility`/`presence` 필드와 월드 좌표의 단위·원점은 이 세션에서 다시 확인하지 못했다(UNVERIFIED, §15 R2).
- **결측 규칙:** `visibility < 0.5`이면 그 랜드마크는 이번 프레임에서 결측으로 본다(§11 V1).
- 공통 모듈은 회전·미러링 보정이 끝난 "세로 기준, 미러링 없음" 좌표만 받는다. 이 보정은 D4 어댑터가 맡는다(D4 P7).
- 좌표는 가로세로 비를 보정해서 쓴다: `x' = x · W/H`, `y' = y`. 이렇게 하면 두 축이 모두 "프레임 높이" 단위가 된다. 이 값은 S를 계산하는 데만 쓰고, 판정 임계값은 모두 S 배수로 표현한다.

### 2.2 입력 추상화: `CameraSource | VideoReplaySource`

두 입력 소스가 **같은** 포즈 추정·특징량·상태머신 파이프라인에 들어간다. 소스에 따라 달라지는 것은 아래 표의 항목뿐이다.

```
FrameSource            (D4 플랫폼 인터페이스)
 ├─ CameraSource       실시간 카메라, MediaPipe LIVE_STREAM 모드
 └─ VideoReplaySource  녹화 파일 디코드, MediaPipe VIDEO 모드, 프레임 드롭 없음
        │
        ▼  PoseFrame { tsMs, poses[≤numPoses]{33 landmarks, world}, source, captureMeta? }
   shared:core  →  대상 고정(§6) → 특징량(§5) → 상태머신(§7) → COUNT(§8) → SpeechOutput / 타임라인
```

| 항목 | `CameraSource` | `VideoReplaySource` |
|---|---|---|
| 타임스탬프 | 센서 타임스탬프(Android `ImageProxy.imageInfo.timestamp`) | 디코드 프레임의 PTS(단조 증가) |
| 드롭 | 네이티브 입력 단에서만 허용하고 드롭 수를 기록한다(D4 P3) | **드롭 0**. 모든 프레임을 순서대로 넣는다 |
| 카메라 피치 φ_cam | 중력 센서로 실시간 측정한다(§3.3) | 녹화할 때 저장한 사이드카 `captureMeta.phiCamDeg`, `vfovDeg`를 쓴다 |
| 용도 | 실사용, 실시간 fps·지연 측정(D6) | **결정적 정확도 검증(필수)**, 회귀 테스트, 추론 fps 측정 |

**VideoReplaySource는 필수다**(2026-09-27 사용자 결정, D4·D6 반영).
- 앱이 녹화한 엄격 세션 영상에는 항상 `captureMeta` 사이드카(φ_cam, VFOV, 엔진·모델, 앱 버전)를 저장한다.
- 외부 영상처럼 사이드카가 없으면 §3의 앙각 검사를 할 수 없다. 이 경우 결과에 `angleCheck = SKIPPED`를 붙이고 엄격 판정 결과는 "참고용"으로만 쓴다(리더보드 제출 불가).
- **결정성 요구:** 같은 영상, 같은 엔진·모델·버전, 같은 delegate(검증은 CPU delegate)라면 카운트와 타임라인이 매번 완전히 같아야 한다(D4 M0 A6: 3회 반복 일치). 기기 간 부동소수점 결과가 비트 단위로 같은지는 UNVERIFIED다. 그래서 기기 간 비교는 "카운트 일치"만 기준으로 삼는다.
- fps 모사: `VideoReplaySource`는 PTS 기반의 결정적 솎아내기로 목표 fps(예: 20)를 흉내 낼 수 있다. 규칙: 직전에 채택한 프레임보다 PTS가 1000/fps_target ms 이상 뒤인 첫 프레임을 채택한다.

### 2.3 타임스탬프

- 모든 시간 계산은 `tsMs`(센서 타임스탬프 또는 PTS를 ms로 바꾼 값)의 차이로 한다. 도착 시각이나 벽시계는 쓰지 않는다.
- 연속 두 프레임의 간격 Δt가 200 ms(`T_gap`)를 넘으면 그 사이 구간은 전 랜드마크 결측으로 본다(§5.4의 유지 규칙이 적용된다).
- 지연 측정 로그에는 `play()`를 호출한 시각을 센서 타임스탬프와 같은 시간축으로 기록해야 한다. 센서 타임스탬프의 시간축(`SENSOR_INFO_TIMESTAMP_SOURCE`: REALTIME 또는 UNKNOWN)은 기기마다 다르다(UNVERIFIED, §15 R5). UNKNOWN이면 프레임 도착 시점에 `elapsedRealtime`과의 오프셋을 기록해 보정한다. 이 보정 오차는 지연 예산 L1 항목에 포함된다.

## 3. 촬영 가이드와 엄격 모드 차단 규칙

### 3.1 권장 배치

| 항목 | 권장 | 판정 방식 |
|---|---|---|
| 방향 | 정면(\|ψ\| ≤ 20°) 또는 45° 사선(30° ≤ \|ψ\| ≤ 60°) | 캘리브레이션 때 ψ로 판별(§4.3) |
| 거리 | 매달린 몸(손목~발목)이 프레임 높이의 **60–90%**를 차지하는 거리 | 안내값. 판정 임계값이 아니다(§3.5) |
| 높이 | 렌즈 높이 1.0–1.5 m 권장. 실제 기준은 높이가 아니라 **β_bar**(§3.3) | β_bar로 판정 |
| 거치 | **폴더블 Flex 모드**(반쯤 접어 세우기, 삼각대 불필요)로 **높은 받침대**(식탁, 선반, 의자 위 상자) 위에 둔다 | 권장 사항 |
| 조명 | 역광(뒤쪽 창) 피하기 | 안내만 |

**Flex 모드 권장 이유.** 사용자의 유일한 실기기가 Galaxy Z Flip7이다(D1). 반쯤 접으면 삼각대 없이 세울 수 있다(Flex 모드 동작은 UNVERIFIED, §15 R7). 다만 바닥에 놓으면 앙각이 너무 커지므로 높은 받침대에 두기를 권한다. **차단 규칙은 "바닥 금지"가 아니라 β_bar 수치로 정의한다.** 바닥에 두더라도 충분히 멀리 두어 β_bar가 기준 안에 들어오면 허용한다.

### 3.2 받침대 높이별 최소 거리 (계산 예)

바 높이 2.3 m, β_bar ≤ 25°(§11 C1 초기값)일 때 최소 수평 거리는 `d_min = (2.3 − h_cam) / tan 25°`(tan 25° ≈ 0.466)다.

| 렌즈 높이 h_cam | 예시 | d_min |
|---|---|---|
| 0.05 m | 바닥 | 4.83 m |
| 0.45 m | 의자 좌판 | 3.97 m |
| 0.75 m | 식탁 | 3.32 m |
| 1.00 m | 식탁 + 상자 | 2.79 m |
| 1.20 m | 선반 | 2.36 m |
| 1.50 m | 높은 선반 | 1.72 m |

거리를 늘리면 몸이 프레임에서 차지하는 비율이 줄어든다. 따라서 60–90% 안내와 d_min을 함께 만족하는 받침대 높이를 앱이 캘리브레이션 화면에서 안내한다. Flip7 후면 카메라의 화각은 UNVERIFIED다. M0에서 실측해 이 표 옆에 "권장 조합"으로 추가한다.

### 3.3 앙각(로우앵글)·부각 차단: 수치 규칙

**근거(시차 오차).** 정면에서 볼 때 TOP 순간의 바는 턱보다 카메라 쪽으로 깊이 `d_depth`(초기 가정 0.10 m, UNVERIFIED)만큼 가깝다. 카메라가 바를 앙각 β로 올려다보면 바와 턱의 겉보기 수직 관계가 약 `d_depth · tan β`만큼 틀어진다.
- 앙각(β > 0, 아래에서 올려다봄): 가까운 바가 더 높아 보인다. 턱이 실제보다 낮게 보이므로 **과소 카운트**(강자 불이익)가 생긴다.
- 부각(β < 0, 위에서 내려다봄): 바가 낮아 보인다. 턱이 실제보다 높게 보이므로 **과다 카운트**(부정 이득)가 생긴다. 그래서 부각 쪽 한도를 더 엄격하게 둔다.
- 예: β = 25°이면 오차 ≈ 0.10 × 0.466 = 0.047 m ≈ **0.12 S**(S ≈ 0.40 m 가정, UNVERIFIED). 또 cos 25° ≈ 0.91이므로 수직 거리가 약 9% 압축된다.

**계산.**
```
φ_cam   = 광축 앙각. 중력 센서 벡터로 계산(위쪽이 +). Replay는 captureMeta.phiCamDeg
off_bar = atan( (0.5 − y_bar) · 2 · tan(VFOV/2) )     # 화면 중심 대비 바의 각도 오프셋
β_bar   = φ_cam + off_bar
```
- VFOV는 카메라 내부 파라미터(초점거리, 센서 크기)로 계산한다. Replay는 `captureMeta.vfovDeg`를 쓴다.
- 캘리브레이션 구간(§4.1) 동안의 β_bar 중앙값으로 판정한다.

| 조건 | 엄격 모드 | 연습 모드 |
|---|---|---|
| β_bar > **+25°** (C1) | `CAL_BLOCK(LOW_ANGLE)`: "기기를 더 높이 두거나 더 멀리 두세요" | 허용 + 경고 배지 |
| β_bar < **−10°** (C2) | `CAL_BLOCK(HIGH_ANGLE)` | 허용 + 경고 배지 |
| −10° ≤ β_bar ≤ +25° | 통과 | 통과 |
| φ_cam 측정 불가(센서 없음, 사이드카 없음) | `angleCheck = SKIPPED`. 실시간이면 차단, Replay면 참고용 | 허용 |

### 3.4 후면 뷰·측면 뷰 차단: 수치 규칙

캘리브레이션 구간의 중앙값으로 판정한다.

| 판별 | 규칙 | 엄격 | 연습 |
|---|---|---|---|
| 후면 뷰 `BACK_VIEW` | FACE 그룹(0, 9, 10) `visibility` 중앙값 < 0.5 **그리고** 어깨(11, 12) `visibility` 중앙값 ≥ 0.8 | 차단 | 허용(보조 지표 a만 사용) + 경고 |
| 측면 뷰 `SIDE_VIEW` | \|ψ\| > 60° (C3) | 차단 | 허용 + 경고 |

후면 뷰에서는 턱 대리점을 관측할 수 없다. 또 좌우 어깨 라벨이 뒤바뀔 수 있어 x 순서로는 판별을 믿을 수 없다(UNVERIFIED). 그래서 얼굴 visibility를 주 기준으로 쓴다.

### 3.5 구도 안내 (판정 아님)

- 몸이 프레임에서 차지하는 비율(손목 y 최소 ~ 발목 y 최대) 60–90%는 **안내값**이다. 판정 임계값이 아니므로 S 배수 규칙의 예외다.
- 엄격 모드에서 캘리브레이션을 통과하려면 손목(15, 16)과 골반(23, 24)이 프레임 안에 있어야 한다. 발목은 무릎을 굽히는 자세를 고려해 필수가 아니다.

## 4. 캘리브레이션과 체형 정규화(S)

### 4.1 절차

1. 사용자가 시작한다(`START`). 화면에 "바에 팔을 펴고 매달리세요"를 띄운다.
2. 대상 고정(§6.1)을 한다.
3. `T_cal = 1000 ms` 동안 연속해서 안정적으로 매달린 구간을 찾는다. 안정 조건: 손목 y의 표준편차 < 0.05 S, SHOULDER·ARM·HIP 그룹이 모두 관측될 것.
4. 이 구간의 중앙값으로 다음을 측정한다: `y_bar`, S, ψ, `θ_hang`, `h_hang`, `a_hang`, `px_ref`, β_bar, FACE visibility.
5. 판정:
   - §3.3·§3.4 차단 조건 → `CAL_BLOCK(사유)`
   - 엄격 모드에서 `θ_hang < θ_ext − 5°` → `CAL_BLOCK(NO_FULL_HANG)`: "팔을 끝까지 펴고 매달리세요"(이 상태로는 무장이 불가능하므로)
   - 그 외 → `CAL_OK`
6. 카운트다운(음성) 후 판정을 시작한다. 카운트다운 시간은 UX 결정 사항이며 D1이 정한다.

측정값은 세트가 끝날 때까지 **고정**한다. 세트 중간에 다시 추정하지 않는다(결정성).

### 4.2 바 높이·턱 기준

- `y_bar` = 캘리브레이션 구간 동안 양 손목(15, 16) y의 중앙값.
- `h_hang` = 같은 구간의 h 중앙값(보통 −1.0 ~ −1.4 S).

### 4.3 어깨폭 S와 요 보정

```
S_2d = median( | P'11 − P'12 | )                       # 가로세로 비 보정 좌표(§2.1)
ψ    = median( atan2( |z_w12 − z_w11| , |x_w12 − x_w11| ) )   # 월드 좌표(m)
S    = S_2d / max(cos ψ, 0.5)
```
- 45° 사선에서는 겉보기 어깨폭이 cos 45° ≈ 0.71배로 줄어든다. 보정하지 않으면 S 배수 임계값이 픽셀 기준으로 더 엄격해진다.
- 월드 좌표 z의 정확도는 UNVERIFIED다. D6에서 정면/45° 조건별로 S 추정의 편차를 기록한다. 편차가 크면 사선 촬영 시 사용자가 방향을 입력하는 방식(정면/45° 선택)으로 대체한다.
- **정규화 원칙:** 정규화 이미지 좌표를 판정 임계값에 직접 쓰지 않는다. 모든 거리는 `(Δ좌표') / S`로 바꾼 뒤 비교한다.

## 5. 전처리와 특징량

### 5.1 처리 순서 (프레임마다)

```
1. 대상 포즈 선택(§6)
2. 랜드마크별 결측 판정(visibility < 0.5)
3. 그룹별 결측 유지(§5.4): 마지막 신뢰값 유지, 최대 300 ms
4. 원시 특징량 계산: θ_L, θ_R, θ, h_raw, a_raw, px_raw
5. 시간 기반 EMA 스무딩(§5.2) → θ, h, a, px (평활값)
6. 이벤트 조건 평가(§7.2) → 상태머신
```

### 5.2 시간 기반 EMA (fps 불변)

```
α(Δt) = 1 − exp(−Δt / τ_EMA),   τ_EMA = 48 ms      # Δt = 33.3 ms(30 fps)이면 α ≈ 0.50
s_t   = α · x_t + (1 − α) · s_{t−1}
```
- EMA는 랜드마크 좌표가 아니라 **스칼라 특징량**(θ_L, θ_R, h, a, px)에 적용한다. 손으로 재현하기 쉽고 결정적이기 때문이다.
- 고정 α를 쓰면 fps에 따라 평활 시간이 달라진다. 시간 상수 τ로 정의하면 fps가 바뀌어도 동작이 같다.
- 지연 효과: 램프 입력에서 지연은 약 `Δt·(1−α)/α`다. 30 fps에서 약 33 ms, 20 fps에서 약 27 ms이며, 예산 L3(≤ 50 ms) 안에 든다. τ를 바꾸면 L3를 다시 계산한다.
- 결측에서 돌아올 때: 유지 시간 안에 복귀하면 EMA를 그대로 이어 간다. 캡을 넘긴 뒤 복귀하면 첫 관측값으로 EMA를 **재초기화**한다(오래된 값이 지연을 만들지 않도록).

### 5.3 특징량 정의

| 특징량 | 산식 | 필요 그룹 |
|---|---|---|
| θ_L, θ_R | ∠(11-13-15), ∠(12-14-16) | SHOULDER, ARM |
| θ | (θ_L + θ_R)/2. 한쪽이 결측이면 다른 쪽 값을 쓰고 `asymUnknown` 플래그 | SHOULDER, ARM |
| `y_chin` (턱 대리점) | 1순위: 입 중점 y(9, 10) + c_chin·S. 2순위(입 결측): 코 y(0) + (c_chin + c_nm)·S | FACE |
| h | (`y_bar` − `y_chin`) / S | FACE |
| a (보조 지표) | (어깨 중점 y − 손목 중점 y) / S | SHOULDER, ARM |
| px | (골반 중점 x' − `px_ref`) / S | HIP |
| H(rep) (키핑) | rep 구간(LEAVE_BOTTOM ~ TOP 확정)에서 \|px\|의 최댓값. D3 §1.2의 H와 같은 정의 | HIP |
| r (연습 전용) | (h − `h_hang`) / (k − `h_hang`) | FACE |

- c_chin = 0.12(입 중점에서 턱 끝까지), c_nm = 0.10(코에서 입까지). 둘 다 인체 치수 가정이며 UNVERIFIED다(§11 G3·G4). D6 라벨 데이터로 보정한다.

### 5.4 가림(결측) 처리와 상단 얼굴 가림

**그룹별 유지 규칙.** FACE, SHOULDER, ARM, HIP 그룹마다 같은 규칙을 적용한다.

1. 그룹의 필수 랜드마크가 결측이면 **마지막 신뢰값(원시값)을 유지**해 EMA에 넣는다.
2. 유지는 첫 결측 프레임부터 최대 **`T_hold` = 300 ms**까지만 한다(캡).
3. 캡을 넘기면 그 그룹의 특징량은 "사용 불가"가 된다. EMA는 동결한다.

**상단 얼굴 가림.** TOP 부근에서 바나 손이 입·코를 가려 FACE visibility가 떨어지는 경우다. TOP 조건은 다음 순서로 평가한다.

| 우선순위 | 조건 소스 | 사용 조건 | TOP 조건 |
|---|---|---|---|
| 1 | 주 지표 h (관측값 또는 300 ms 이내 유지값) | FACE를 쓸 수 있음 | h ≥ h_line |
| 2 | **보조 지표 a** | FACE 캡 초과, 그리고 SHOULDER·ARM을 쓸 수 있음 | a ≤ d_aux (0.45) |
| 3 | 없음 | 둘 다 쓸 수 없음 | → `UNDECIDABLE` 이벤트(§7.2) |

- h_line: 엄격 모드는 `k`, 연습 모드는 `h_hang + 0.6·(k − h_hang)`(즉 r ≥ 0.6).
- 연습 모드에서 보조 지표 a를 쓸 때의 TOP 조건: `a ≤ a_hang − 0.6·(a_hang − d_aux)`.
- **소스 전환 규칙:** TOP 조건이 전환 전후 모두 참이면 체류 타이머를 리셋하지 않는다.
- 보조 지표로 TOP 확정된 rep에는 `AUX` 플래그를 붙인다. D3는 이 rep을 `UNDETERMINED_OCCLUSION`(카운트는 포함, 하위 점수는 제외)으로 다룬다.
- 판정 불가(`UNDECIDABLE`) rep은 **엄격·연습 모두 노카운트**다. 사유는 `UNDETERMINED_OCCLUSION`이다. "노카운트" 음성을 쓰지 않고 짧은 중립 톤으로 구분한다. 태그도 일반 노카운트 사유(`INCOMPLETE_EXTENSION` 등)와 다르다.
- TOP_OFF의 히스테리시스: 주 지표는 `h < h_line − 0.05 S`(`h_top`), 보조 지표는 `a > d_aux + 0.05 S`(`h_aux`).
- **지연 AC 적용 범위:** 유지값 또는 보조 지표 경로로 확정된 rep은 최대 300 ms가 추가로 늦어질 수 있다. 이런 rep에는 `latencyPath = HOLD | AUX`를 기록하고, D6 지연 AC 집계에서는 따로 보고한다(§16 이슈 3).

### 5.5 대상 소실과 매달림 해제

- **소실(LOST):** 추적이 끊겼거나(§6.2) HIP·SHOULDER 4점(11, 12, 23, 24)이 모두 사용 불가인 상태가 **`T_lost` = 1000 ms** 계속되면 발생한다.
- **매달림 해제(자동 종료):** 양 손목이 바에서 떨어진 상태(`(y_wrist − y_bar)/S > 0.5`)가 **`T_release` = 2000 ms** 계속되면 `STOP`을 낸다. 스펙의 "매달림 해제 감지 시 자동 종료" 요구사항이다.

## 6. 다인 처리: 대상 고정

### 6.1 캘리브레이션 시 고정

- 포즈 엔진 설정은 `numPoses = 2`(초기값, 튜닝 범위 2–3)다. MediaPipe `num_poses`의 기본값은 1이다(VERIFIED §15 R1). 1로 두면 다른 사람이 대신 추정될 수 있으므로 2 이상으로 둔다. 추론 비용이 얼마나 늘어나는지는 M0에서 측정한다(UNVERIFIED).
- 고정 대상은 **바 영역과 겹치는 인물 중 가장 큰 인물**이다.
  - 바 영역과 겹친다: 양 손목이 모두 관측되고, 두 손목의 y 차이 < 0.3 S이며, 손목이 프레임 상단 절반 안에 있다.
  - 크기: SHOULDER·HIP 4점 경계 상자의 면적.
- 고정한 대상의 `S_lock`(= S)과 몸통 중심점 `c`(11, 12, 23, 24의 평균)를 기록한다.

### 6.2 추적

- 매 프레임, 이전 대상 중심점에서 **가장 가까운** 후보를 고른다. 단 거리가 `g_track = 1.0 S` 이하여야 한다(게이트).
- 게이트 안에 후보가 없으면 그 프레임의 대상은 결측이다(§5.4 적용). 이 상태가 1000 ms 계속되면 LOST(§5.5)다.
- 교차 위험: 두 사람의 중심점이 겹쳐 지나가면 ID가 뒤바뀔 수 있다. 완화책으로, 후보의 어깨폭이 `S_lock`의 ±20% 밖이면 후보에서 뺀다. 이 완화책의 효과는 UNVERIFIED이며 D6의 "2인 등장" 세트로 검증한다.

### 6.3 재고정 (PAUSED에서 복귀)

다음 조건을 모두 만족하는 후보가 **`T_found` = 300 ms** 연속 관측되면 `FOUND`를 낸다.
- 마지막 대상 중심점에서 1.5 S 이내
- 어깨폭이 `S_lock`의 ±20% 이내
- 바 영역과 겹침(§6.1)

재고정할 때는 캘리브레이션 값을 **유지**한다(S, `y_bar`를 다시 측정하지 않는다). 조건을 만족하는 후보가 없으면 PAUSED를 유지한다. 다른 사람으로 **자동 전환하지 않는다**.

- **조건이 참이고 현재 상태에서 전이가 정의된** 첫 이벤트 하나만 적용한다. 프레임당 전이는 최대 1회다.

3. **이중 카운트 방지.** TOP에 머무는 동안 DWELL_OK 조건이 계속 참이어도 COUNT는 다시 일어나지 않는다.

## 8. 단일 카운트 이벤트

> **COUNT (이 문서에서 유일한 카운트 정의).**
> 상태가 **PULLING**(무장: 직전 BOTTOM에서 신전 확정 — 엄격 θ ≥ θ_ext가 T_ext_hold 동안 유지, 연습 r ≤ 0.4)이고, 그 프레임에 **TOP 확정**(E8 DWELL_OK: TOP 조건 연속 ≥ T_dwell, 또는 E9 FAST_TOP)이 발생했으며, 가드 G1(엄격 모드 키핑)을 통과했을 때, **그 프레임에서 정확히 1회** 발생한다.
> 발생 즉시 파이프라인 스레드에서 다음을 한다(D4 P6): ① 사전 합성 숫자 클립 `play()` 호출(Android `SoundPool`; 100을 넘으면 TTS), ② 카운터 +1, ③ `topMs = ts`와 rep 지표 스냅샷 기록.

- 엄격 모드에서 BOTTOM 신전이 확정되지 않은 채 TOP에 도달하면 COUNT가 아니라 N1(노카운트)이다(§7.3의 HANG_WAIT·DESCENDING 행).
- 문서의 다른 절은 모두 이 정의를 참조만 하며, 새로운 카운트 조건을 추가하지 않는다.

### 8.1 T_dwell 오판 리스크와 해소 규칙 (FAST_TOP)

- **리스크:** 폭발적인 강자 rep은 상단 체류가 60 ms 정도로 짧을 수 있다. T_dwell = 100 ms만 쓰면 이 rep을 놓친다(**과소 카운트 = 강자 불이익**). 반대로 T_dwell을 낮추면 바 부근에서 1프레임짜리 노이즈 스파이크를 카운트할 위험이 커진다.
- **해소 규칙:** TOP 확정에 FAST_TOP(E9)을 추가한다. 원시 h가 **바 라인 + 0.10 S 이상으로 분명히** 넘은 구간이 **50 ms 이상** 이어지면, 평활값 체류가 T_dwell보다 짧아도 TOP으로 확정한다.
  - 30 fps 단일 프레임 스파이크(구간 33 ms)는 걸러진다. 2프레임(구간 67 ms)이면 통과한다.
  - 20 fps에서는 1프레임도 구간이 50 ms이므로 통과한다. 이는 알려진 한계다: 20 fps에서는 노이즈 내성이 줄어든다. D6에서 20 fps 모사(§2.2)로 오카운트율을 측정한다.
- FAST_TOP은 원시 h가 내려가는 프레임에 발생하므로, TOP 최초 충족으로부터 대략 원시 구간 길이(보통 < T_dwell) 뒤에 온다. 따라서 지연 예산(L4 ≤ 100 ms)을 넘지 않는다.
- FAST_TOP으로 확정된 rep에는 `FAST_TOP` 플래그를 붙인다(§12.1). D6은 FAST_TOP rep의 정·오카운트를 따로 집계한다.
- T_dwell의 튜닝 상한은 **150 ms**다(지연 예산 여유 때문, §10).

## 9. rep 시간 검사 (T_floor / T_rep_min) — 서버와 같은 값을 공유

- **rep 시간** d = `endMs − startMs`. `startMs`는 LEAVE_BOTTOM(A4) 시점, `endMs`는 그다음 EXT 확정(A6) 시점이다. 즉 완전 신전 → TOP → 완전 신전 한 주기다.

| 구간 (엄격 모드, 카운트된 rep) | 판정 | 클라이언트 처리 | 서버(D5) |
|---|---|---|---|
| d < **T_floor = 500 ms** | 물리적으로 불가능 | 카운트와 음성은 이미 발생했으므로 되돌리지 않는다. rep에 `TOO_FAST` 플래그. **이 세션은 리더보드 제출 불가**(사유 `REP_TOO_FAST`)로 표시하고 리포트에 안내 | 제출이 오면 거부(사유 코드) |
| 500 ≤ d < **T_rep_min = 800 ms** | 빠르지만 가능(강자) | `FAST_REP` 플래그. 제출 가능 | `flagged = true` + 운영자 알림. **거부·숨김 없음** |
| d ≥ 800 ms | 정상 | — | — |
| `endMs = null` (마지막 rep에서 신전 전에 바를 놓음) | 판정 보류 | `NO_END` 플래그. 타임라인에는 남기되 세션 기록 개수와 제출 `reps`에서 제외 | 제출 `reps`와 모든 물리 일관성 검사에서 제외(D5 §M4.6b) |

- T_floor 근거(2.2A, UNVERIFIED): 엄격 rep은 대략 팔 길이(0.5–0.6 m)만큼 올라갔다 내려온다. 0.5초면 평균 속도가 2 m/s를 넘고 방향 전환이 두 번 있어야 하므로, 사람이 반복할 수 있는 범위 밖으로 본다.
- 두 값은 **초기값**이다. D6에서 정상 엄격 rep 시간 분포(최단값, 하위 1%)로 확정한다: T_floor는 거부 오탐 0건을 데이터로 확인할 만큼 낮게, T_rep_min은 하위 1% 부근.
- 클라이언트와 서버는 **같은 값**을 쓴다. 타임라인 헤더의 `thr.tf`, `thr.tr`에 판정에 쓴 값을 싣는다(§12.2).
- 고정 rep 수 상한은 두지 않는다(강자 불이익 금지 원칙, D1·D5).

## 10. 지연 예산

### 10.1 구간 정의

- **내부 구간(로그로 측정):**
  - 시작 = TOP 조건이 **원시 랜드마크 기준으로** 처음 충족된 프레임의 센서 타임스탬프(원시 h ≥ h_line인 첫 프레임).
  - 종료 = 음성 클립 **`SoundPool.play()` 호출** 시각. SoundPool에는 재생 시작 콜백이 없으므로 호출 시각을 끝점으로 삼는다(콜백 부재는 UNVERIFIED(저위험), §15 R4).
- **외부 구간(240fps 슬로모션으로 측정):**
  - 시작 = 물리적으로 턱이 바를 넘는 순간.
  - 종료 = 실제 소리가 나기 시작한 순간(음성 파형 시작).

### 10.2 예산표 (각 항목 ↔ D6 측정 방법 1:1)

| # | 항목 | 예산 (ms) | 구간 | D6 측정 방법 |
|---|---|---|---|---|
| L0 | 프레임 양자화(물리 TOP ~ 다음 캡처 프레임) | ≤ 50 (20 fps 기준, 30 fps면 ≤ 33) | 외부 | 슬로모션(외부 합계에 포함) |
| L1 | 센서 → 분석기 프레임 전달 | ≤ 50 | 내부 | 로그: `t_sensor` → `t_analyze_in` |
| L2 | 포즈 추론 | ≤ 80 | 내부 | 로그: `t_analyze_in` → `t_result` |
| L3 | EMA 스무딩 지연 (τ = 48 ms, 30 fps에서 α ≈ 0.5, 약 1프레임) | ≤ 50 | 내부 | 로그: 원시 TOP 첫 프레임 ts → 평활 TOP 첫 프레임 ts |
| L4 | T_dwell (FAST_TOP 경로는 ≤ T_dwell) | 100 | 내부 | 로그: 평활 TOP 첫 프레임 ts → TOP 확정 프레임 ts |
| L5 | 상태머신 + 디스패치 | ≤ 5 | 내부 | 로그: TOP 확정 프레임 `t_result` → `t_play` |
| **내부 합계** | L1 + L2 + L3 + L4 + L5 | **≤ 285** (목표 p95 ≤ 300) | 내부 | 로그 종단값: `t_play − t_sensor(원시 TOP 첫 프레임)` |
| L6 | 오디오 출력 지연 (`play()` → 소리) | ≤ 100 | 외부 | 슬로모션 외부값 − 내부 로그값 − L0 추정치 |
| **외부 합계** | L0 + 내부 + L6 | **≤ 435** (여유 65) | 외부 | 슬로모션: 턱이 바를 넘는 프레임 ↔ 음성 파형 시작, rep ≥ 50개 |

- **수용 기준(사용자 확정):** 외부 측정 **p95 ≤ 500 ms 그리고 최대 ≤ 600 ms**. 예산 합계 435 ms는 500 ms 이하다.
- 외부 측정만이 실제 소리 발생의 판정 근거다. 내부 로그는 원인을 분해하는 데 쓴다.
- L6이 M0/D6에서 100 ms를 넘으면 저지연 경로(AAudio/Oboe 또는 `AudioTrack` 저지연 모드)로 교체한다. 이는 D4 결정 항목이다.
- T_dwell을 올리면 L4가 그대로 늘어난다. 튜닝 상한 150 ms에서 외부 합계는 485 ms다.
- τ_EMA를 바꾸면 L3를 다시 계산한다.
- **예외 경로:** `latencyPath = HOLD | AUX`인 rep(§5.4)은 최대 300 ms가 추가될 수 있다. AC 모집단에서 따로 떼어 보고한다(§16 이슈 3).
- 음성 준비: 숫자 1–100과 "노카운트" 클립은 사전 합성해 세션 시작 때 `SoundPool`에 로드한다. 100 초과는 TTS를 쓰고, 세션 시작 때 TTS 엔진을 prewarm한다(계획 §6 리스크 완화).

## 12. rep 지표와 메타데이터 타임라인 스키마

### 12.1 사유 코드와 플래그 (공통 enum)

사유는 D3 §4의 `FailureTag`와 이름을 맞췄다.

| 값 | 사유 (하위 3비트) | 의미 |
|---|---|---|
| 0 | `COUNTED` | COUNT 발생(§8) |
| 1 | `INCOMPLETE_EXTENSION` | 무장하지 않고 TOP 도달(N1) |
| 2 | `CHIN_BELOW_BAR` | 시도했으나 TOP에 도달하지 못함(A5) |
| 3 | `KIPPING` | 엄격 모드 키핑 가드(G1) |
| 4 | `UNDETERMINED_OCCLUSION` | 판정 불가(N4) |
| 5 | `ABORTED` | 소실·종료로 폐기(A10). 타임라인에만 기록 |

| 비트 | 플래그 | 의미 |
|---|---|---|
| 8 | `FAST_TOP` | FAST_TOP으로 TOP 확정(§8.1) |
| 16 | `AUX` | 보조 지표로 TOP 확정(§5.4) → D3는 `UNDETERMINED_OCCLUSION`으로 취급(카운트 포함, 채점 제외) |
| 32 | `FAST_REP` | T_floor ≤ d < T_rep_min |
| 64 | `TOO_FAST` | d < T_floor |
| 128 | `NO_END` | `endMs = null` |

`code = 사유 + 플래그 비트합`. 예: 보조 지표로 카운트된 빠른 rep = 0 + 16 + 32 = 48.

### 12.2 rep 지표 (로컬, D3 입력)

rep 후보마다 `shared:core`가 만드는 로컬 레코드다. 업로드하지 않는다.

```
RepMetrics {
  index: Int                  // 세트 내 순번(노카운트 포함)
  startMs, topMs, endMs?: Long  // 세션 시작 기준 상대 ms. topMs = TOP 확정(또는 NC) 시점
  reason: ReasonCode; flags: Int
  thetaBottomL, thetaBottomR: Float   // 직전 BOTTOM 신전 확정 시점(A3/A6)
  thetaTopL, thetaTopR: Float         // TOP 확정 시점
  hPeak: Float                        // rep 구간 평활 h 최댓값(S)
  kipH: Float                         // H(rep) = max|px| (S), D3 §1.2
  durationMs: Long?                   // endMs − startMs
  latencyPath: NORMAL | FAST_TOP | HOLD | AUX
}
```

### 12.3 업로드 타임라인 (텍스트 JSON, ≤ 16 KB)

리더보드 제출(엄격 모드만)과 운영자 판단에 쓴다. 영상 없이 개연성을 판단하는 근거다(D5). 크기 하드 상한은 16 KB다(D5 §M4.6a).

**로컬 기록 개수와의 일치.** 세션 기록(히스토리)과 리더보드 제출의 개수는 `n`과 같다. 즉 `NO_END` rep은 실시간 음성으로는 카운트되었더라도 세션 기록 개수에서 제외하고, 리포트에 "마지막 rep 미완료(신전 전 종료)"로 표시한다. 타임라인 `r`에는 그대로 남긴다(D5 §M4.6b).

```json
{
  "v": 1,
  "app": "1.0.0(12)",
  "eng": "mediapipe-pose-lite/1.0.0",
  "src": "cam",
  "mode": "S",
  "dur": 184233,
  "fps": 29.6,
  "beta": 18,
  "view": "F",
  "thr": {"te": 160, "k": 0, "td": 100, "tf": 500, "tr": 800},
  "n": 42,
  "fmt": "full",
  "r": [[1520, 640, 780, 15, 168, 0], [210, 610, 800, 12, 166, 32]]
}
```

| 필드 | 의미 |
|---|---|
| `v` | 스키마 버전 |
| `app`, `eng` | 앱 버전(빌드), 포즈 엔진/모델/버전(D4 결정 기록) |
| `src` | `cam` \| `replay` |
| `mode` | `S`(엄격). 연습 세션은 업로드하지 않음 |
| `dur` | 세션 길이 ms(START 이후 첫 CAL_OK ~ ENDED) |
| `fps` | 분석 fps p50 |
| `beta`, `view` | β_bar(정수 °), 뷰 `F`(정면) \| `D`(사선) |
| `thr` | 판정에 쓴 임계값: θ_ext, k, T_dwell, T_floor, T_rep_min |
| `n` | 제출 카운트 수 = `r` 중 **사유 0(`COUNTED`)이면서 `NO_END` 플래그가 없는** 항목 수. 서버 `REP_COUNT_MISMATCH` 검사의 "유효 rep 수"와 같은 정의이고(D5 §M4.4·§M4.6b), 제출 필드 `reps`와 같아야 한다 |
| `fmt` | `full` \| `compact` \| `gz` |
| `r[i]` (full) | `[dS, dT, dE, pk, eb, code]` |
| `dS` | 이 rep의 `startMs` − 직전 rep의 `endMs`(첫 rep은 세션 시작 기준). 이전 rep이 `NO_END`이면 직전 `topMs` 기준 |
| `dT` | `topMs − startMs` (올라가는 템포) |
| `dE` | `endMs − topMs` (내려가는 템포). 없으면 −1 |
| `pk` | round(hPeak × 100) (0.01 S 단위) |
| `eb` | round(θ_bottom 좌우 평균) ° |
| `code` | §12.1 |

- **ROM 요약** = `pk`(상단 여유)와 `eb`(하단 신전). **템포** = `dT`, `dE`. **유효/노카운트 사유** = `code`의 하위 3비트.
- 타임스탬프는 모두 세션 상대 ms이고 단조 증가한다. 누적합으로 절대 시각을 복원할 수 있다. 서버는 비단조, `n` 불일치, `n × T_floor > dur`를 검사한다(D5).

**크기 보장 (고정 rep 상한 없음).**

| 형식 | 항목 예 | rep당 크기 | 헤더 | 16 KB 하드 상한 안에 들어가는 rep 수 |
|---|---|---|---|---|
| `full` | `[1520,640,780,15,168,0],` | 약 24 B | 약 260 B | 약 670 |
| `compact` (`pk`, `eb` 생략) | `[1520,640,780,0],` | 약 17 B | 약 260 B | **약 947**(D5 §M4.6a 기준값) |
| `gz` (compact를 gzip 후 base64) | — | 압축률 UNVERIFIED | — | 그 이상. 압축률은 D6/M4에서 실측 |

- 타임라인 크기의 하드 상한은 **16 KB/세션**이다(D5 §M4.6a). 클라이언트는 `full` → `compact` → `gz` 순으로 16 KB 안에 들어가는 첫 형식을 고른다.
- rep 수만으로는 제출을 막지 않는다(고정 rep 상한 없음). 상한 16 KB는 `compact` 형식에서 약 947 rep에 해당한다.

## 13. 합성 골든 케이스

### 13.1 합성 규약 (`shared:core` 단위 테스트에서 그대로 사용)

- 입력은 **특징량 수준**의 원시 트랙이다: θ(t)(좌우 동일), h_raw(t), a_raw(t), px_raw(t), 그룹별 visibility, 필요하면 두 번째 인물의 트랙. 테스트는 §5.1의 4단계(원시 특징량) 뒤에 주입해 EMA, 상태머신, COUNT, 타임라인을 검증한다. 랜드마크 → 특징량 변환은 별도 단위 테스트로 다룬다(§16 이슈 6).
- 샘플링: 30 fps, `ts_n = floor(n · 1000 / 30)` ms(정수). 세션 시작 ts = 0.
- 캘리브레이션: 0–1000 ms 기본 매달림 트랙 + `captureMeta`(φ_cam, VFOV)를 준다. 기본 조건은 β_bar = +10°, ψ = 0°, FACE vis 0.95. START는 ts = 0에 주입하고, CAL_OK는 약 1000 ms에 발생한다.
- 기본 매달림 트랙: θ = 170°, h = −1.2, a = 1.5, px = 0, 전 그룹 vis 0.95. 이때 `h_hang` = −1.2, `a_hang` = 1.5, `θ_hang` = 170°. 연습 모드 h_line = −1.2 + 0.6·1.2 = **−0.48**.
- 표준 rep 템플릿 R(t0, P): 키프레임 사이는 선형 보간한다(상대 ms 기준).
  - θ: 0 → 170, 600 → 40, 600+P → 40, 1200+P → 170
  - h: 0 → −1.2, 600 → +0.2, 600+P → +0.2, 1200+P → −1.2
  - a: 0 → 1.5, 600 → 0.3, 600+P → 0.3, 1200+P → 1.5
  - px: 0
  - 기본 P = 300.
- 손계산은 α = 0.5로 근사한다(실제 α는 Δt 33/34 ms에서 0.497–0.507). 따라서 테스트는 **카운트 수·사유·플래그는 정확히** 비교하고, **이벤트 시각은 표의 창(±) 안에 있는지**로 비교한다.
- R(t0, 300)의 손계산 기준값:
  - 원시 h ≥ 0 첫 충족: t0 + 514
  - 평활 h ≥ 0: 약 t0 + 567
  - DWELL_OK → COUNT: 약 t0 + 667, 창 [t0+630, t0+720]
  - LEAVE_BOTTOM: 약 t0 + 133
  - EXT 복귀: 약 t0 + 1250 + P
  - rep 시간 ≈ 1417 ms, 창 [1350, 1480]

## 16. 미해결 이슈

1. ~~D3와의 정합(가림 rep 처리)~~ **해결:** D3가 D2와 일치하도록 갱신됨(`AUX` rep = 카운트 포함 + 채점 제외, `UNDECIDABLE` = 노카운트). 연습 모드의 두 ROM 정의(D2 수직 상승 비율 r, D3 팔꿈치 ROM_ratio)의 겹침은 D6 데이터로 확인한다.
2. ~~`NO_END` rep의 서버 처리~~ **해결(D5 §M4.6b):** `NO_END` rep은 제출 `reps`와 모든 물리 일관성 검사에서 제외하고, `REP_COUNT_MISMATCH`의 유효 개수에서도 뺀다. D2 §9·§12.3에 반영.
3. **가림 경로의 지연 AC 적용 범위.** `HOLD`/`AUX` 경로 rep은 최대 300 ms가 늦어질 수 있어 "최대 ≤ 600 ms"를 넘을 수 있다. 제안: AC 모집단에서 따로 떼어 보고한다. D6와 리드의 확인이 필요하다.
4. ~~타임라인 크기~~ **해결(D5 §M4.6a):** 하드 상한 16 KB/세션(`compact` 약 947 rep). rep 수만으로 거부하지 않는 원칙 유지. D2 §12.3에 반영.
5. **β_bar 임계값의 사용성.** +25°에서 식탁 높이(0.75 m) 거치는 3.3 m 이상 떨어져야 한다. 실내 공간이 부족하면 상한을 +30°로 완화할지를 D6 조건 매트릭스(앙각별 ±1 비율)로 결정한다.
6. **랜드마크 수준 골든 테스트.** §13은 특징량 주입 방식이다. 랜드마크 → 특징량 변환(턱 대리점, S 요 보정)을 검증하는 소수의 테스트는 구현 단계에서 추가한다.
