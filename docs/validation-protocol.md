## 1. 원칙과 측정 경로

### 1.1 두 측정 경로

| 경로 | 입력 | 측정 대상 | 기기 |
|---|---|---|---|
| **영상 재생 경로(결정적)** | `VideoReplaySource`(D2 §2.2, D4 §3.1): 녹화 파일 디코드, MediaPipe `VIDEO` 모드, 드롭 0, CPU delegate | 카운트 정확도(AC1), 노카운트 재현율(AC2), 채점 결정성(AC7), 리포트 내용(AC6), 임계값·가중치 확정, 포즈 엔진 정확도 비교, 회귀 | 개발 PC의 JVM 테스트 또는 Flip7. 중급기 불필요 |
| **실기기 경로(실시간)** | `CameraSource`: CameraX Preview + ImageAnalysis + VideoCapture | 지연(AC3), fps(AC4), 오프라인 동작(AC5) | Galaxy Z Flip7 |

- **정확도는 영상 재생 경로가 1차 판정 경로다.** 같은 입력(영상 + `captureMeta` 사이드카), 같은 엔진·모델·버전, 같은 delegate, 같은 임계값 버전이면 카운트와 타임라인이 매번 완전히 같다(D4 §3.1 결정성 조건 4개). 따라서 실시간 카메라 없이, 중급기 없이도 n ≥ 100세트 판정을 반복할 수 있다.
- 실시간 fps·지연만 실기기로 잰다. 실기기 결과는 매번 조금씩 다르므로 분포(p50/p95/p5/최대)로만 보고한다.
- 판정에 쓴 버전 묶음(앱 버전, 포즈 엔진·모델·버전, delegate, D2 임계값 세트 버전, D3 가중치 버전)을 모든 결과 파일에 기록한다. 버전 묶음이 다르면 결과를 비교하지 않는다.

### 1.2 기준 기기와 상태

| 기기 | 역할 | 상태 |
|---|---|---|
| **Galaxy Z Flip7** (SM-F766N, Exynos 2500, Android 16 / API 36, 12 GB, 후면 카메라 하드웨어 레벨 FULL — adb 확인) | 개발·M0·지연 측정·오프라인 측정. fps는 **성능 상한 참고치** | 보유 |
| 중급기(mid-tier) | "중급기 ≥ 20 fps" AC(AC4)의 대상 | **DEFERRED** — 실기기 확보 시 수행. 사용자는 출시 전 중고 중급기를 구매하지 않기로 결정 |
| 외부 촬영 기기(240fps 슬로모션) | 외부 지연 측정(§5.2) 전용 | 별도 기기 필요. 확보 방법·모델은 `docs/private/dataset.md`에 기록 |

## 2. 데이터셋

### 2.1 단계적 수집

| 단계 | 규모 | 시점 | 용도 | 한계 |
|---|---|---|---|---|
| **1차** | **30세트** | M1 종료 조건 | 스모크 테스트, **회귀 탐지 전용**(§12), 임계값 튜닝(§9, §10) | 30세트로는 "95%" 주장 불가(§4.3). AC 판정에 쓰지 않는다 |
| **최종** | **≥ 100세트** (평가 세트) | **M4 이전 완료** | AC1·AC2 판정, 포즈 엔진 비교(§7), D3 가중치 확정(§8) | — |

- **튜닝과 평가의 분리:** 임계값·가중치 튜닝에 쓴 세트는 평가 n에 넣지 않는다. 1차 30세트를 튜닝에 썼다면 평가 세트 ≥ 100세트는 별도로 모은다.
- 평가 결과를 보고 임계값을 다시 바꿨다면, 그 평가 세트는 튜닝 세트로 옮기고 새 세트를 추가 수집해 다시 판정한다(같은 데이터로 튜닝과 판정을 동시에 하지 않기 위함).

### 2.2 피험자와 조건 매트릭스

- **피험자 ≥ 5명.** 체형(어깨폭·키), 숙련도(엄격 1–5회 수준부터 20회 이상 강자까지), 성별을 섞는다. 최소 1명은 빠른 rep(상단 체류 짧음)을 하는 숙련자를 포함한다(FAST_TOP·T_rep_min 검증용).
- 피험자별 동의(초상권·영상 보관·용도)와 인적 정보는 `docs/private/dataset.md`에만 기록한다.

**조건 매트릭스(2 × 2 × 2 × 2 = 16칸):**

| 요인 | 수준 1 | 수준 2 |
|---|---|---|
| 조명 | 밝음(주광·실내 조명 충분) | 저조도 또는 역광 |
| 거리 | 근거리(전신이 프레임 높이의 약 90%) | 원거리(약 60%) — D2 §3.5 구도 안내 범위의 양 끝 |
| 각도 | 정면 | 45° 사선 |
| 복장 | 몸에 붙는 옷 | 헐렁한 옷(긴팔·후드) |

- 최종 평가 세트에서 **각 칸 ≥ 5세트**(16 × 5 = 80) + 나머지는 §2.3의 특수 세트로 채운다.
- 카메라 피치는 D2 §3.3 허용 범위 안에서 찍되, 최종 세트 중 일부는 β_bar 상한 부근(+20° ~ +30°)으로 찍어 D2 §16 이슈 5(+25° → +30° 완화 여부)를 판단한다(§10).
- 차단 조건(로우앵글 초과·후면 뷰) 영상은 소수(≥ 5개) 따로 찍어 **캘리브레이션 차단이 동작하는지**만 확인하고, 정확도 n에는 넣지 않는다.

### 2.3 세트 구성

| 구분 | 비율·개수 (최종 평가 세트 기준) | 내용 |
|---|---|---|
| 정상 세트 | 나머지 | 규칙대로 수행 |
| **의도적 오류 세트** | **≥ 30%** (≥ 30세트) | 하프렙, 턱 미달, 하단 불완전 신전, 엄격 모드 키핑을 섞음. 세트당 오류 rep ≥ 4개 → **오류 rep 합계 ≥ 100개**(§4.4 재현율 모수) |
| 상단 얼굴 가림 세트 | ≥ 10세트 | 바·손이 입·코를 가리는 그립·각도. `HOLD`/`AUX`/`UNDECIDABLE` 경로 검증(D2 §5.4) |
| 2인 등장 세트 | ≥ 5세트 | 대상 뒤·옆으로 다른 사람이 지나가거나 옆 바에서 운동. 대상 고정 검증(D2 §6) |
| 고반복 세트 | ≥ 3세트, 각 ≥ 30회 | 강자 불이익 금지 확인(고정 rep 상한 없음) |
| 빠른 rep 세트 | ≥ 5세트 | rep 시간 0.5–0.8초 구간, 상단 체류 < 100 ms(FAST_TOP, D2 §8.1) |

- 세트 길이는 1–5회, 6–15회, 16회 이상이 고르게 섞이도록 한다(오차 ±1의 의미가 세트 길이에 따라 다르기 때문).
- 세트가 여러 구분에 동시에 속할 수 있다(예: 저조도 × 가림). 비율은 세트 단위로 센다.

### 2.4 녹화 규약과 보관 위치

- 앱의 녹화 경로로 찍는다: 720p / 30fps / 목표 1.0 Mbps(D4 §7), `captureMeta` 사이드카(φ_cam, VFOV, 엔진·모델, 앱 버전) 필수. 사이드카가 없는 영상은 `angleCheck = SKIPPED`이므로 엄격 판정 평가에서 제외한다(D2 §2.2).
- 추가로 원본 해상도(1080p/30fps 이상) 사본을 함께 보관하면 분석 해상도 변경(D4 저하 사다리 ①) 시 재평가에 쓸 수 있다.
- 세트 ID 체계, 파일 위치, 피험자 매핑은 `docs/private/dataset.md`에 둔다. tracked 문서와 결과 보고서에는 세트 ID와 조건 코드만 쓴다.

## 3. 라벨링

### 3.1 2인 독립 카운트와 합의

1. 라벨러 2명이 **서로 결과를 보지 않고** 같은 영상을 라벨링한다. 0.25배속·프레임 단위 재생을 허용한다.
2. 각 라벨러는 세트마다 **엄격 모드 카운트**와 **연습 모드 카운트**를 따로 기록한다(같은 영상을 두 규칙으로 본다). 엄격 규칙 = D2 §8 COUNT 정의(하단 θ ≥ 160° 수준의 신전 + 턱이 바 위), 연습 규칙 = 오르내림(ROM ≥ 60%).
3. 두 라벨러의 카운트가 다르면 둘이 함께 영상을 다시 보고 합의한다. 합의가 안 되면 제3자가 결정한다. 최종값 = **합의 라벨(ground truth)**.
4. 합의 전 일치율(세트 단위 카운트 완전 일치 비율)을 기록한다. **목표 ≥ 90%.** 이보다 낮으면 라벨링 가이드(판정 경계 예시 영상 포함)를 고치고 불일치 세트를 다시 라벨링한다. 라벨 품질이 낮으면 AC1 판정 자체를 믿을 수 없기 때문이다.
5. 라벨러는 앱 출력을 보지 않고 라벨링한다(앵커링 방지).

### 3.2 rep별 타임스탬프와 오류 유형 라벨

rep 시도마다 다음을 기록한다(라벨 파일 스키마와 위치는 `docs/private/dataset.md`).

| 필드 | 내용 |
|---|---|
| `startMs` | 하단 완전 신전에서 올라가기 시작한 프레임 |
| `topMs` | 턱이 바를 처음 넘은 프레임(턱 미달 rep은 최고점 프레임) |
| `endMs` | 다음 하단 완전 신전 프레임 |
| `strictValid` | 엄격 모드 유효 여부 |
| `errorType` | `HALF_REP` / `CHIN_BELOW_BAR` / `INCOMPLETE_EXTENSION` / `KIPPING` / `OCCLUDED` / 없음 |
| `postureGrade` | 5개 채점 항목별 사람 등급(1–5) — §8 가중치 확정용, 세트 단위 |

- 타임스탬프는 영상 PTS 기준(ms)이다. 앱 타임라인과 같은 시간축이므로 rep 단위 매칭(§4.2)에 쓴다.
- rep 시간 d = `endMs − startMs`(D2 §9와 같은 정의)로 §9 분포를 만든다.

## 4. 카운트 정확도 (AC1, AC2)

### 4.1 VideoReplaySource 결정적 실행

- 평가 세트 전체를 `VideoReplaySource`로 돌린다: 드롭 0, MediaPipe `VIDEO` 모드(동기 호출), **CPU delegate 고정**, 엔진·모델 버전 기록(D4 §3.1).
- **결정성 확인:** 같은 기기·같은 빌드로 평가 세트를 **3회** 돌려 세트별 카운트와 타임라인이 완전히 같아야 한다(D4 M0 A6과 같은 기준). 하나라도 다르면 결함이며, 원인을 고치기 전에는 정확도 결과를 채택하지 않는다.
- 기기 간(PC JVM vs Flip7) 부동소수점 결과의 비트 동일성은 UNVERIFIED다(D2 §15 R11). 기기 간 비교는 **세트별 카운트 일치**만 기준으로 한다.
- 실행 결과(세트별 앱 카운트, 타임라인, 버전 묶음)는 기계가 읽을 수 있는 파일로 저장한다. 같은 입력 → 같은 출력이므로, 이 파일이 회귀 기준선(§12)이 된다.

### 4.2 정확도 지표와 합격 기준

세트 i의 오차 `e_i = 앱 카운트 − 합의 라벨 카운트`.

| 지표 | 정의 | 합격 기준 | 역할 |
|---|---|---|---|
| **±1 비율 (주 지표, AC1)** | \|e_i\| ≤ 1인 세트 수 / n | **n ≥ 100세트에서 ≥ 95%** (엄격 모드) | **게이트** (사용자 확정) |
| ±2 비율 | \|e_i\| ≤ 2인 세트 비율 | 100% 목표 | **보조 지표만**. 미달 세트는 원인 분석 대상이지만 게이트가 아님 |
| 평균 절대 오차 MAE | 평균 \|e_i\| | 기록 | 추세 확인 |
| 부호 편향 | 평균 e_i | 기록 | 과소(강자 불이익) / 과다 카운트 경향 |
| 연습 모드 ±1 비율 | 연습 규칙 합의 라벨 대비 | 기록(엄격과 같은 95% 목표) | 보조. 엄격 모드가 리더보드 반영 대상이므로 게이트는 엄격 모드 |

- **rep 단위 매칭(원인 분석용):** 앱 COUNT 시점(`topMs`)과 라벨 `topMs`를 ±300 ms 창으로 1:1 매칭해 정카운트(TP), 오카운트(FP, 라벨에 없는 카운트), 놓침(FN)을 센다. 세트 오차가 ±1이어도 FP 1 + FN 1로 상쇄된 경우를 찾아낸다.
- 오차 원인은 세트마다 태그를 붙인다(가림, 2인, 조명, 키핑 판정, 빠른 rep 등) → §10 튜닝 우선순위.

### 4.3 Wilson 신뢰구간과 표본 수 해석

관측 비율 p̂ = k/n의 95% Wilson 점수 구간(z = 1.96)으로 "참 비율"의 하한을 보고한다.

```
하한 = ( p̂ + z²/(2n) − z·√( p̂(1−p̂)/n + z²/(4n²) ) ) / ( 1 + z²/n )
```

| 관측 | n | 관측 비율 | Wilson 95% 하한 | 해석 |
|---|---|---|---|---|
| 95 / 100 | 100 | 95.0% | **≈ 88.8%** | **합격선.** 관측 95%라도 참 비율은 88.8%까지 낮을 수 있음을 함께 보고 |
| 96 / 100 | 100 | 96.0% | ≈ 90.2% | |
| 98 / 100 | 100 | 98.0% | ≈ 93.0% | |
| 190 / 200 | 200 | 95.0% | ≈ 91.0% | 표본을 늘리면 하한이 올라감 |
| **30 / 30** | 30 | 100% | **≈ 88.6%** | 전부 맞혀도 하한이 88.6% |
| 29 / 30 | 30 | 96.7% | ≈ 83.3% | |

- **30세트로는 "95%" 주장을 할 수 없다.** 30/30이어도 하한이 88.6%이기 때문이다. 그래서 1차 30세트는 회귀 탐지용으로만 쓰고, AC1은 최종 평가 세트(n ≥ 100)로만 판정한다.
- **합격 판정은 관측 비율(≥ 95%)로 한다**(사용자 확정). Wilson 하한은 판정 조건이 아니라 **보고 의무 항목**이다. 결과 보고서에는 항상 "k/n, 관측 비율, Wilson 95% 구간"을 함께 적는다.

### 4.4 엄격 모드 노카운트 재현율

- 모수: 합의 라벨에서 `strictValid = false`인 rep 시도(하프렙, 턱 미달, 하단 불완전 신전, 엄격 키핑). **≥ 100개**(§2.3 오류 세트 설계로 확보).
- 재현율 = 앱이 카운트하지 않은(노카운트 처리한) 오류 rep 수 / 오류 rep 수.
- **합격 기준(AC2): 재현율 ≥ 90%.** 참고로 90/100의 Wilson 하한은 ≈ 82.6%이며 함께 보고한다.
- **노카운트 피드백 확인:** 노카운트된 오류 rep 중 "시도" 기준(팔꿈치를 θ_attempt 이하까지 굽힘, D2 §11.1 A3)을 넘은 rep에서 노카운트 음성/시각 피드백이 나왔는지 타임라인의 사유 코드(D2 §12.1)로 확인한다. 기준: 해당 rep의 **100%**에 노카운트 사유 코드가 기록됨.
- 역방향 오류도 기록한다: **오노카운트율** = 합의 라벨상 유효 rep 중 앱이 노카운트한 비율(강자 불이익). 목표 ≤ 2%(보조, 게이트 아님).

### 4.5 하위 집계

전체 결과와 별도로 다음 하위 집단의 ±1 비율·재현율·rep 매칭 결과를 따로 보고한다. 하위 집단은 표본이 작으므로 게이트가 아니라 **약점 탐지용**이다.

- 조건 매트릭스 16칸별, 요인별(조명·거리·각도·복장)
- 가림 세트: `AUX` 경로 rep의 정카운트율, `UNDECIDABLE` rep 수(D2 §5.4), D3 `UNDETERMINED_OCCLUSION` 처리 일치
- 2인 세트: 대상 전환(ID 뒤바뀜) 발생 수(D2 §16 이슈 7)
- `FAST_TOP` 플래그 rep의 정·오카운트(D2 §8.1). **20 fps 모사**(D2 §2.2 PTS 솎아내기)로 같은 세트를 다시 돌려 오카운트율을 비교
- 고반복 세트: 후반 rep(피로로 ROM 감소)의 판정 일치

## 5. 지연 (AC3)

두 방법으로 잰다. **AC3 판정 근거는 외부 측정(방법 2)뿐이다**(실제 소리 발생 시점은 외부에서만 보이기 때문). 내부 로그(방법 1)는 원인 분해용이다. 각 항목은 D2 §10.2 예산표와 1:1로 대응한다.

공통 조건: Flip7, `CameraSource`, **녹화 on**(720p/30/1.0 Mbps), 채택 포즈 엔진, 사전 합성 클립 + `SoundPool`(D4 §6), 미디어 볼륨 고정, 기기 스피커 출력(블루투스 금지 — 블루투스 오디오 지연은 범위 밖).

### 5.1 방법 1: 내부 로그

- 구간: **TOP 조건이 원시 랜드마크 기준으로 처음 충족된 프레임의 센서 타임스탬프 → `SoundPool.play()` 호출 타임스탬프**(D2 §10.1).
- 로그 필드: `t_sensor`, `t_analyze_in`, `t_result`, 평활 TOP 첫 프레임 ts, TOP 확정 프레임 ts, `t_play`, `latencyPath`(`NORMAL` / `HOLD` / `AUX`), `FAST_TOP` 여부. 이 필드로 L1–L5를 분해한다(D2 §10.2).
- 시간축: `t_play`는 센서 타임스탬프와 같은 시간축으로 기록한다. 센서 시간축이 UNKNOWN이면 `elapsedRealtime` 오프셋으로 보정한다(D2 §2.3, UNVERIFIED R5).
- 표본: 방법 2와 **같은 세션**의 모든 카운트 rep(≥ 50개).
- **목표: `NORMAL` 경로 p95 ≤ 300 ms**(예산 합 ≤ 285 ms). 이 목표를 못 넘고 외부 측정은 합격이면 AC3는 합격이지만, 초과 항목(L1–L5)을 미해결 이슈로 등록한다.

### 5.2 방법 2: 외부 240fps 슬로모션

- 장비: 오디오 트랙이 함께 기록되는 **240fps 카메라**(외부 촬영 기기, §1.2). 피험자 측면에서 바·턱과 Flip7 스피커가 한 화면에 들어오도록 찍는다.
  - 슬로모션 모드에서 오디오가 기록되는지는 기기마다 다르다(UNVERIFIED). 오디오가 없으면 **오디오가 기록되는 최고 fps 모드(예: 120fps)**로 찍고, 늘어난 프레임 양자화 오차(120fps면 ±8.3 ms)를 결과에 명시한다.
- 측정: 영상의 **턱이 바 윗면을 처음 넘는 프레임** 시각 ↔ **음성 파형 시작**(무음 구간 대비 진폭이 처음 뚜렷하게 오르는 지점) 시각의 차이. 프레임 단위 재생 도구와 파형 편집기를 쓴다.
- 판독 신뢰도: 전체 rep의 20%를 제2 판독자가 다시 재서 차이가 ±2프레임(240fps에서 ±8.3 ms) 안인지 확인한다.
- 표본: **rep ≥ 50개**, 피험자 ≥ 3명, 정면·45° 모두 포함, 연속 세트(한 세트 여러 rep)로 수집.
- 백분위수 계산: nearest-rank 방식. p95 = 오름차순 ⌈0.95·n⌉번째 값(n = 50이면 48번째). 즉 50개 중 최대 2개만 500 ms를 넘을 수 있다.
- **합격 기준(AC3, 사용자 확정): `NORMAL` 경로 rep에서 p95 ≤ 500 ms 그리고 최대 ≤ 600 ms.** `NORMAL` 경로 rep이 50개 미만이면 추가 수집한다.
- 파생: L6(오디오 출력 지연) ≈ 외부값 − 내부 로그값 − L0 추정치(D2 §10.2). **L6 p95 > 100 ms면 저지연 오디오 경로(AAudio/Oboe 또는 `AudioTrack` 저지연 모드)로 교체**한다(D4 §6).
- 외부 측정 rep과 내부 로그 rep은 rep 순번과 시각으로 1:1 매칭해 `latencyPath`를 붙인다.

### 5.3 가림 폴백 rep의 분리 보고

`latencyPath = HOLD | AUX`인 rep(상단 얼굴 가림으로 유지값 또는 보조 지표 경로로 TOP이 확정된 rep, D2 §5.4)은 설계상 최대 300 ms(`T_hold` 캡)가 추가로 늦어질 수 있어 **600 ms를 넘을 수 있다**(D2 §16 이슈 3).

| 항목 | 처리 |
|---|---|
| AC3 판정 모집단 | **`NORMAL` 경로 rep만.** `HOLD`/`AUX` rep은 p95·최대 계산에서 뺀다 |
| 분리 보고 | `HOLD`/`AUX` rep의 개수, 전체 대비 비율, p50 / p95 / 최대를 AC3 결과표에 **별도 행**으로 항상 적는다 |
| 결함 기준 | `HOLD`/`AUX` rep의 외부 지연이 **900 ms(= 600 + 300 캡)를 넘으면 결함**으로 보고 고친다(캡이 지켜지지 않았다는 뜻) |
| 비율 감시 | 가림 세트가 아닌 표준 조건 세트에서 `HOLD`/`AUX` 비율이 20%를 넘으면, 폴백이 예외가 아니라 일상 경로가 된 것이므로 촬영 가이드·랜드마크 결측 원인을 조사한다. 조사 결과는 AC3 보고서에 첨부 |
| 사용자 고지 | 가림 구간에서 음성이 늦을 수 있다는 점은 촬영 가이드(D2 §3.5 구도 안내)에서 안내 |

## 8. D3 가중치 확정 절차

D3 §8(v0 → v1)을 D6 데이터로 실행하는 방법이다.

1. **데이터:** 평가 세트 n ≥ 100세트 각각에 대해 (a) D3 v0 산식의 하위 점수 5개·세션 점수(영상 재생 경로로 결정적 계산), (b) 라벨러 2명이 독립으로 매긴 항목별 사람 등급(`postureGrade`, 1–5)과 전체 등급을 기록한다. 두 라벨러의 등급 차이가 2 이상인 항목은 합의로 정한다.
2. **정합성 분석:** 항목별로 v0 하위 점수와 사람 등급의 Spearman 순위 상관을 구한다. 상관이 0.5 미만인 항목은 산식(태그 임계값 포함) 점검 대상으로 표시한다. 산식 형태 변경은 이 절차 밖(D3 major 개정)이다.
3. **가중치 재추정:** 사람 전체 등급을 하위 점수 5개로 설명하는 가중치를 **제약 조건 아래에서** 구한다: 각 가중치는 v0 ±0.10 범위, 합 = 1.00, 음수 금지(D3 §8.3).
4. **검증(분할):** 세트를 무작위가 아닌 **세트 ID 순 홀짝**으로 둘로 나눠(결정적 분할) 한쪽으로 추정, 다른 쪽에서 세션 점수 ↔ 사람 전체 등급 Spearman을 v0와 비교한다. **+0.05 이상 개선될 때만** v1 가중치를 채택한다. 개선이 없으면 v0 값을 그대로 확정값으로 선언한다(값은 같고 표기만 "확정").
5. **팁 선택 확인:** 확정 가중치로 재채점한 결과에서 리포트의 교정 팁 1–3개가 사람이 지적한 주요 문제와 겹치는 비율을 기록한다(보조).
6. **버전 증가:** D3 상단 버전과 변경 이력에 값·근거 n·날짜를 기록하고, 저장 리포트에 가중치 버전을 남긴다(D3 §8.4–8.5).

## 9. T_floor / T_rep_min 확정 절차

D2 §9·§11.1 T4/T5의 초기값(T_floor 500 ms 거부, T_rep_min 800 ms FLAG)을 데이터로 확정한다. **서버(D5 M4.3)와 같은 값**을 쓰므로 D2·D5를 함께 갱신한다.

1. **분포 수집:** 튜닝 세트 + 평가 세트 전체에서 합의 라벨상 **유효 엄격 rep**의 rep 시간 d = `endMs − startMs`(§3.2)를 모은다. 피험자별·세트별로 최단값, 하위 1%, 하위 5%, 중앙값, 표본 수를 기록한다. 빠른 rep 세트(§2.3)와 숙련 피험자를 반드시 포함한다.
2. **T_floor(거부):** 최단 정상 rep보다 **확실히** 낮게 둔다.
   - 후보 = min(500 ms, 0.8 × d_min)을 50 ms 단위로 내림.
   - 확인: 데이터셋의 유효 엄격 rep 중 d < T_floor인 rep이 **0건**(거부 오탐 0건).
   - 데이터셋에 최상위 강자가 없을 수 있으므로 **초기값 500 ms보다 올리지 않는다.** 올리려면 별도의 빠른 rep 전용 수집이 필요하다.
3. **T_rep_min(FLAG):** 하위 1% 부근에 둔다.
   - 후보 = 유효 엄격 rep 시간의 하위 1% 값을 50 ms 단위로 반올림, 범위 [T_floor + 100 ms, 1000 ms]로 제한.
   - 확인: FLAG가 붙는 **정상 세트 비율 ≤ 5%**(운영자가 처리 가능한 수준). 넘으면 후보를 50 ms씩 내린다.
4. **부정 테스트 연계:** 확정값으로 D5 M9 부정 테스트 (3)·(3b)(< T_floor 거부, T_floor 이상 T_rep_min 미만은 FLAG만·노출 유지)를 다시 확인한다.
5. **기록:** D2 §11.1 T4/T5 초기값 → 확정값, D5 M4.3 같은 값, 타임라인 헤더 `thr.tf`/`thr.tr`(D2 §12.2)의 값을 같은 날 함께 갱신한다. 확정 근거(분포 표, n, 날짜)는 이 문서 결과 보고서에 남긴다.
6. **출시 후 재확인:** FLAG된 제출(D5 M4.5)의 rep 시간 분포가 쌓이면 분기별로 T_rep_min을 다시 본다. 고정 rep 수 상한은 어떤 경우에도 도입하지 않는다.

## 10. 그 밖의 D2 임계값 확정 절차

D2 §11에서 "확정 = D6"인 임계값을 **튜닝 세트**로 정한다.

1. 우선순위(오차 원인 태그 빈도 순으로 재정렬 가능): θ_ext(A1) → k(B1) → κ_kip(B6) → T_dwell(T1) → d_aux(B4) → δ_fast(B3) → τ_EMA(E1) → visibility 기준(V1).
2. 한 번에 1개씩, D2 §11 튜닝 범위 안에서 격자 탐색한다. 목표 함수 순서: ① ±1 비율, ② 노카운트 재현율, ③ 오노카운트율(강자 불이익) 낮음.
3. 제약: T_dwell ≤ 150 ms(지연 예산), T_hold ≤ 300 ms, 모든 거리 = S 배수·시간 = ms(단위 규칙 유지).
4. **β_bar 상한(C1):** 조건 매트릭스의 앙각별 ±1 비율로 +25°를 +30°로 완화할지 정한다(D2 §16 이슈 5). +25~+30° 구간 세트의 ±1 비율이 전체와 5%p 이상 차이 나지 않으면 완화한다.
5. D3와의 ROM 정의 겹침(D2 §16 이슈 1): 연습 모드에서 D2 r ≥ 0.6 카운트와 D3 ROM_ratio < 0.6 불완전 판정의 교차표를 기록한다.
6. 확정값은 D2 §11 "초기값" 열 옆에 기록하고 임계값 세트 버전을 올린다. 확정 후 평가 세트로 §4를 1회 판정한다(§2.1 분리 원칙).

## 12. 회귀 정책

| 계층 | 대상 | 실행 시점 | 합격 기준 |
|---|---|---|---|
| R0 단위 테스트 | D2 §13 골든 케이스, D3 §6 결정성(10회 반복), D3 §7 워크드 예제 | `shared:core`의 모든 변경(CI) | 전부 통과 |
| R1 회귀 세트 | **1차 30세트**를 `VideoReplaySource`로 실행 | `shared:core` 판정·채점 로직, 임계값, 포즈 엔진·모델, 디코드·전처리 코드 변경 시 | 기준선 대비 세트별 카운트 변화가 있으면 **세트마다 원인 설명 필수**. ±1 세트 수가 기준선보다 줄면 불합격 |
| R2 전체 평가 | 최종 평가 세트(≥ 100) | 출시 후보 빌드마다, 그리고 포즈 엔진·모델·임계값 세트·가중치 버전이 바뀔 때 | §11 AC1·AC2·AC6·AC7 기준 |
| R3 실기기 | 지연(§5)·Flip7 fps(§6.2) | 포즈 엔진·해상도·오디오 경로·녹화 프리셋 변경 시, 그리고 출시 후보마다 | §11 AC3 기준, Flip7 B4 p50 ≥ 20 / p5 ≥ 15(참고) |

- **기준선:** R1·R2 결과 파일(세트별 카운트·타임라인·점수 + 버전 묶음)을 기준선으로 저장한다. 결정적 실행이므로 코드가 안 바뀌면 결과도 한 글자도 안 바뀌어야 한다. 바뀌면 그 자체가 신호다.
- **의도된 변화:** 임계값·가중치 변경처럼 결과가 바뀌는 게 의도된 경우, 변화 세트 목록과 이유를 변경 기록에 남기고 새 기준선으로 교체한다.
- **데이터셋 동결:** 평가 세트 구성은 버전으로 동결한다. 세트를 추가하면 데이터셋 버전을 올리고, 이전 버전과의 비교는 공통 세트로만 한다.
- **튜닝 누수 금지:** §2.1 분리 원칙을 지킨다. 평가 세트 결과를 보고 임계값을 바꿨다면 해당 세트는 튜닝 세트로 옮긴다.
- 결과 보고서의 세트 식별은 세트 ID·조건 코드만 쓴다. 피험자 정보는 `docs/private/dataset.md`에만 있다.
